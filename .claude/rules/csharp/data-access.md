# EF Core and data access

## Contexts and migrations
- One `DbContext` per module, with its own default schema (`modelBuilder.HasDefaultSchema(...)`) and
  `ApplyConfigurationsFromAssembly`. Entity configuration lives in `IEntityTypeConfiguration<T>` classes, not
  attributes.
- Migrations are per module and generated by the tool, never written by hand:
  `dotnet ef migrations add <Name> --project <Module>.Infrastructure --startup-project src/Web.Api --context <Module>DbContext --output-dir Database/Migrations`
  (the `dotnet-ef-migration` skill). Review `Up()` and `Down()` before committing.
- Migration names say what changed: `AddInvoiceTable`, `AddStatusToInvoice`, `RenameXToY`.
- A model change ships with its migration in the same commit. Migrations are generated code: exclude them from
  analyzers, do not reformat them.
- Production applies an idempotent SQL script (`dotnet ef migrations script --idempotent`), reviewed like code.

## Queries
- Parameterised always; `FromSqlInterpolated`/`FromSql` only with interpolation that EF parameterises, never
  `FromSqlRaw` with concatenated input.
- Read paths: `AsNoTracking()` and projection. Paginate every list; no unbounded `ToListAsync()` on user-facing
  queries. Watch for N+1 (use `Include` or projection deliberately).

## Multi-tenancy
- Tenant-scoped entities implement the repo's tenant marker and are filtered by a global query filter set in the
  base context; handlers do not hand-write tenant `Where` clauses, and never take the tenant from a request header,
  query or route when a token claim exists.
- `IgnoreQueryFilters()` only in code that must cross tenants, with a comment saying why.

## PostgreSQL (Npgsql)
- `UseSnakeCaseNamingConvention()` with `ComplexProperty(...).ToJson()` conflicts: clear the column names of the
  complex type's properties after `ToJson()`.
- `timestamptz` with `DateTimeOffset` or UTC `DateTime`; never local time.

## Packages
- Pin package versions (no floating `*`). Enable `NuGetAudit` in `Directory.Build.props`. Do not commit NuGet
  `packages.lock.json` in a cross-platform team.
